Configuration Outline

Build the settings structure

Click a type to add it to the active section, or drag it directly into a target section. Selecting an item activates the section containing it. While dragging, moving near the top or bottom edge scrolls the page automatically.

Dropping on the canvas background moves an existing item back to the root. Empty builder and inspector areas intentionally contain no instructional text so the workspace stays as large as possible.

Structure

Section enums

A Section enum is an enum controller whose values become visible settings pages. Section enums can be nested. Their sections can be reordered horizontally and moved between containers.

Properties

Settings and runtime behavior

The Properties panel edits the selected item. Section enums normally use Stored only, because RML already handles their navigation. Numeric range validation can require a maximum value and enables the scalar slider. Hidden settings remain stored in the configuration even when they are not editable in the RML UI.

Vector editors use one field per component. List-style editors use one value per line where applicable.

Typed runtime graph

Pack into Node

Pack into Node replaces the visual configuration outline with an automatically synchronized typed runtime graph. Returning to the outline preserves the packed graph. Reloading starts in the outline while keeping graph nodes and wires saved.

The Generated file selector is available in both Configuration Outline and Typed Runtime Graph. Both views expose the same live generated project manifest, but keep independent selections: the Outline defaults to the main configuration/mod source, while the graph defaults to its generated runtime-graph source. The selector updates automatically when graph nodes add, remove or rename generated outputs.

Settings preview

Preview behavior

Preview changes remain session-local until applied or saved. The Full Color Picker keeps its profile and strength behavior. The adaptive color-picker fit script is loaded only on viewports that need it.

Local data

Projects, autosave and privacy

The current draft is saved automatically in this browser. A JSON project file creates a portable backup that can be reopened on this or another device. The builder runs entirely in the browser; source code and configuration data are not uploaded by the builder.

Generated project

Export

Generated projects target .NET 10 for the current Resonite/RML setup. The Resonite installation path is used for local assembly references. MSBuild variables such as $(HOME) are supported, and ResonitePath can still be overridden when building.

Multiple selected files are bundled into one ZIP. When an early Harmony patch library is present, the ZIP contains separate Mod and Patches project folders plus build scripts. Their project files deploy the compiled DLLs to rml_mods and rml_libs respectively. The Export dialog renders the exact live package manifest rather than a hard-coded list, so later generator extensions appear automatically.

Interactive onboarding

Guided first-steps tour

The Tour button starts the same visual assistant that appears on the first launch. It spotlights the relevant control while the rest of the screen is dimmed. Each step animation repeats automatically until you press Next, Back or Skip, so no gesture is missed. The assistant only demonstrates the workflow: the builder state is snapshotted before the tour and restored when you finish or skip it.

Node library

Search-on-demand API catalog

The live Resonite API catalog is searched on demand so opening the graph does not create thousands of DOM buttons. Enter at least two characters in the node search to query catalog-generated API nodes. Search results are capped; refine broad searches when necessary.

Typed connections

Configuration sockets and wires

● Stored value ▶ Startup ■ Saved ◆ Startup + saved

Wire colors represent value types. Startup and Saved configuration sockets can connect to matching value inputs and impulse inputs; Stored sockets remain value-only. Incompatible sockets are disabled while a connection is being created.

Dropping an output wire on empty graph space creates a monitor. Dropping a value-input wire can create a self-contained constant or context source. Impulse inputs and multi-input runtime operations must be connected explicitly.

Scanner runtime bridge

Live Display Value and Display Impulse

Display Value and Display Impulse prefer values published by the matching generated mod running inside Resonite. The generated runtime discovers the scanner mod without a compile-time dependency, and the scanner streams each monitor update to this builder over its local loopback SSE bridge.

Matching uses the generated namespace/class channel plus the stable graph node id. After adding, deleting or replacing a monitor, rebuild and reload the generated mod. When the scanner or matching mod is unavailable, the node clearly falls back to Runtime Only and keeps the existing local graph preview where that value can be evaluated safely.

Add Display Value (RML Menu) in Configuration Outline, then pack the outline. That item appears as its own dedicated output on the Start node. Every graph Display Value has a second RML Menu input. One Start-node display output may fan out to multiple Display Value or Display Impulse nodes. Display Impulse has the same optional RML Menu input and contributes its live pulse counter. By default, every connected runtime value stays side by side in one single RML menu row; the row does not wrap values into a vertical list. Select the Display Value (RML Menu) item in Properties to set their left-to-right order. If a vertical list is actually wanted, enable Stack values vertically there; the same order controls top-to-bottom placement in that mode. The graph wires define membership and the inspector defines presentation—there is no source dropdown.

Typed collections

For Each, Collect To List and indexed access

For Each accepts any scanner-derived or built-in type that implements System.Collections.IEnumerable. Its collection and item generics are linked: connecting a typed collection automatically infers the exact element type, while the zero-based Index and current Item remain valid for the duration of each Body impulse. Completed fires after the final item and also for empty or null collections.

Example: Focused World → Get · World.AllUsers → For Each, then connect Item to a User property such as Get · User.UserName and run logging or other logic from Body. Arrays, generic lists, dictionary key/value collections and custom catalog types implementing IEnumerable<T> use the same node. Asynchronous enumerables are intentionally separate and are not executed by this synchronous node.

Get Item At Index reads one zero-based item from any synchronous typed collection. Its Collection and Item generics are linked exactly, so List<User> produces User and List<string> produces string. Item returns the type default for an invalid index, while Success reports validity and Count exposes the current collection size.

Collect To List is a separate stateful collection node. Reset clears its strongly typed List<T>, Add appends the current Value, and the List and Count outputs expose the complete current result. For a fresh scan, connect the trigger to Reset, Reset Done to For Each.Call, For Each.Body to Add, and the per-item mapped value to Value. The List output can feed Display Value, another For Each node, object inputs and compatible standard .NET collection-interface inputs. If one impulse output fans out to several direct Reset or Add targets, the generated runtime performs every direct sibling mutation first and only then follows their Reset Done / Added continuation paths. A later sibling reset therefore cannot erase values produced by an earlier continuation loop.

Dynamic configuration controls

Collection-backed controls from the runtime graph

Mark as Editable on Collect To List exposes a generated Dynamic Choice entry in the Configuration Outline node palette. It does not insert a setting merely when enabled. If it is later switched back to false, any Dynamic Choice previously materialized from that exact collection is removed from Configuration Outline automatically, because the collection is no longer an editable RML source.

Click or drag that generated palette node into the exact Outline position you want. Only then is the dynamic setting created and, after packing, exposed on the Start / Configuration node. The Dynamic Choice binds directly to the marked Collect To List source: no Display Value/helper node and no separate Labels/Stable Values source selection is required. Because that collection exists only at runtime, Properties only offers a Default selection while the matching generated mod is actually running and its runtime list is available. The Builder subscribes to that runtime channel directly, so Properties and Preview update as soon as the list arrives or changes; no unrelated click or rerender is required. Without an explicit valid default, the first runtime item is selected automatically (unless Allow empty selection is enabled). The generated Start-node string output resolves to that same effective selection as soon as the collection changes, so graph logic never remains on an empty raw configuration value while the menu already shows a valid first item. It can be wired freely into Equal, Select, Branch/flow logic, method calls, stores, or any other compatible typed runtime logic. Dynamic controls retain their exact global Configuration Outline position among ordinary settings and Runtime Display rows.

Graph interaction

Move, resize and route

Drag nodes to move them. Resize from the right edge, bottom edge or lower-right corner. Double-click a resize grip to reset that axis. Wires can contain movable bend points and branches. The graph toolbar can center the graph or clear operator nodes while retaining the packed configuration node.

Explicit scroll-layer selection works throughout the whole builder, not only inside the runtime graph. Hold Ctrl (Command on macOS) and use the wheel to choose a level. The hierarchy is captured from the first gesture and remains frozen while the modifier is held: moving the mouse into Properties, Generated Project Files, another node or a dialog does not replace that hierarchy. A new session starts at the outermost available level. From there, the selectable hierarchy follows visual reading order: the real visual hierarchy: each parent is visited before its descendants. Sibling or independent regions are read top to bottom and, when they share a row, left to right. A region is completed depth-first before the selector moves to a later sibling region below. Wheel down advances through that order and Wheel up walks it backward. The selector has no hard beginning or end: continuing in the same direction wraps around to the opposite end and repeats the hierarchy. The currently previewed boundary itself glows; no separate corner status box is shown. Releasing the modifier enables a global scroll override. Every subsequent Wheel event is captured before nested panels and native browser scrolling, and is routed only to the locked level regardless of cursor position. Shift does not release the selection/override only when that exact selected level has a real horizontal scroll axis; Shift + Wheel then scrolls that same level horizontally. On a level without horizontal scrolling, Shift releases the selection/override like any other non-Ctrl/Command key. Any other key (including Tab, Escape, Enter, arrows or text input) and any pointer press (mouse, touch or pen; any mouse button) releases it without consuming the original input. Reaching an edge, becoming empty, or being temporarily rerendered never silently transfers scrolling to another level. Only layers with a genuinely visible, unobscured area participate: elements outside the viewport or fully covered by a higher stacking layer (for example underneath the sticky header, a dialog or an overlay) are excluded. Partially covered layers remain selectable through their still-visible area.

The final outermost level is always the actual <html> element. Inside the Typed Runtime Graph the virtual Graph ROOT therefore appears one level before <html>, rather than replacing the page root. The <html> level remains selectable even when it has no overflow; in that case it is shown as an empty level. If a browser uses a different document.scrollingElement, that real document scroll surface is inserted immediately inside the still-present empty <html> level.

The level list is not a hard-coded set of panels. A new selection session is built from the current composed DOM path and real overflow dimensions, then locked by stable identities so dynamically rerendered elements can rebind without changing the chosen level. Dynamically rendered nested Section enums, real scrollable graph-node bodies, dialog lists and future scroll containers therefore participate automatically. A future custom surface can also declare data-rml-scroll-layer="auto" (or "always" for an intentionally selectable empty level) and a stable data-rml-scroll-layer-key without changing the selector.

Harmony load phases

Main mod patches and early rml_libs patches

Harmony Patch Event, lifecycle patch presets and scanner-generated Harmony API calls stay in the main mod project. They are registered when the mod reaches OnEngineInit, because their callbacks may emit graph impulses and access generated runtime state.

Harmony Exact Patch Source also stays in the main project, but its attribute patches are now registered automatically with one guarded PatchAll call. Use Early Harmony Patch Library (rml_libs) only when a patch must be active before normal rml_mods are loaded. That node creates an independent project and DLL and cannot depend on graph sockets or main-mod configuration state. It can only target assemblies already available before rml_mods are loaded; patches for another normal mod belong in the main mod phase. Automatic discovery of the early DLL requires the matching custom ResoniteModLoader build containing the generated-library marker support.

Low-level HarmonyLib nodes produced by the API scanner are kept under Advanced / Raw C#. They expose the scanned API but do not infer patch signatures, callback methods or load phase automatically.

Expert fallback

Advanced / Raw C#

Manual usings, references, source files, compiler overrides and reflection-oriented fallback nodes stay hidden unless Show Advanced / Raw C# is enabled. Prefer normal typed catalog nodes whenever a direct node exists.

Complete built-in runtime nodes

Node reference

This is the complete reference for the builder's fixed built-in runtime nodes. Every registered built-in node is documented here, including palette-hidden helper nodes. Advanced / Raw C# nodes are deliberately separated from the normal typed nodes so it is clear when the builder can no longer provide the same level of type and dependency safety.

Catalog-generated Resonite API nodes are version-derived rather than fixed builder nodes. The reference reports the complete currently registered catalog count, while Node Search remains the authoritative live index for each generated Type, Enum, Constructor, Method, Property, Field and Event node. HarmonyLib catalog calls are classified as Advanced / Raw C# because they expose low-level runtime APIs without inferring patch signatures or an early rml_libs load phase.

Dynamic settings

Collection-backed Dynamic Choice

A Collect To List node marked Editable contributes one generated Dynamic Choice entry to the Configuration Outline palette. The entry is only a creation option until you explicitly click or drag it.

Once placed in the Outline, the control uses the marked runtime collection as its only option source and is emitted as a normal typed Start / Configuration output after packing. No Labels/Stable Values monitor selection is needed. A Default selection can only be picked while the matching generated mod is running and the runtime list is available. The direct runtime subscription refreshes Properties and Preview immediately when that list changes; otherwise the first runtime item is used automatically unless empty selection is explicitly allowed. The Start-node value follows that effective runtime selection immediately when the collection changes. The control keeps its exact global Outline position among normal settings and Runtime Display rows. No setting is auto-inserted merely by enabling Mark as Editable.
